## 1. Why Complexity Matters

একটি সমস্যা অনেক ভিন্ন উপায়ে সমাধান করা যায়। যেমন, দশ লাখ নামের একটি তালিকা থেকে একটি নাম খুঁজে বের করতে প্রতিটি নাম একে একে দেখা যায়, আবার অনেক বুদ্ধিমান পদ্ধতিও ব্যবহার করা যায়। দুটি পদ্ধতিই সঠিক উত্তর দেবে, কিন্তু একটি চোখের পলকে শেষ হতে পারে, আরেকটিতে কয়েক মিনিট লাগতে পারে।

**Complexity Analysis** হলো এমন একটি পদ্ধতি, যার মাধ্যমে আমরা কোনো Algorithm চালানোর **আগেই** তার কার্যকারিতা পরিমাপ করতে এবং একাধিক Algorithm-এর মধ্যে তুলনা করতে পারি।

আমরা দুটি বিষয় পরিমাপ করি:

| পরিমাপ | যে প্রশ্নের উত্তর দেয় |
|---|---|
| **Time Complexity** | Input বাড়লে চলার সময় কত দ্রুত বাড়ে? |
| **Space Complexity** | Input বাড়লে Memory-এর ব্যবহার কত দ্রুত বাড়ে? |

**Stopwatch দিয়ে সময় (সেকেন্ড) মাপলেই কেন যথেষ্ট নয়?** কারণ ফলাফল Computer-এর গতি, Programming Language, Compiler এবং একই সময়ে চলা অন্যান্য কাজের ওপর নির্ভর করে। ধীর Computer-এ দ্রুত Algorithm-ও ধীর মনে হতে পারে। তাই এমন একটি পরিমাপ দরকার, যা নির্দিষ্ট Machine-এর ওপর নির্ভর করে না।

## 2. Input Size and Counting Operations

ধারণাটি সহজ:

- Input Size-কে **n** ধরি (Array-এর Element-এর সংখ্যা, Linked List-এর Node সংখ্যা, কোনো সংখ্যার Digit-এর সংখ্যা ইত্যাদি)।
- Algorithm n-এর ওপর নির্ভর করে মোট কতগুলো **Basic Operation** করে তা গণনা করি। Comparison, Assignment, Arithmetic Operation, Array Element Access হলো Basic Operation।
- n খুব বড় হলে এই গণনা কীভাবে **বাড়ে**, সেটিই আমরা দেখি।

**উদাহরণ:** Array-এর সব Element-এর যোগফল।

```cpp
int sum = 0;                    // 1টি Operation
for (int i = 0; i < n; i++) {   // Loop n বার চলে
    sum += a[i];                // প্রতিবার 1টি Operation
}
return sum;                     // 1টি Operation
```

মোট Operation প্রায় `n + 2`। n = 10,00,000 হলে কাজ প্রায় দশ লাখ ধাপ। n-এর তুলনায় "+ 2" নগণ্য। এই পর্যবেক্ষণ থেকেই Asymptotic Notation-এর ধারণা এসেছে।

## 3. Time Complexity

**Time Complexity** হলো Input Size n-এর একটি Function হিসেবে Algorithm-এর Basic Operation-এর সংখ্যা।

তিনটি ভিন্ন Algorithm-এর Operation Count-এর Function তুলনা করা যাক:

| n | Algorithm A: 5n | Algorithm B: n² | Algorithm C: 2ⁿ |
|---|---|---|---|
| 10 | 50 | 100 | 1,024 |
| 100 | 500 | 10,000 | 1.27 × 10³⁰ |
| 1,000 | 5,000 | 10,00,000 | অকল্পনীয়ভাবে বিশাল |

n ছোট হলে পার্থক্য বোঝা কঠিন। n বড় হলে পার্থক্য বিশাল। Complexity Analysis বড় n-এর জন্য এই **Growth Rate-এর** ওপর মনোযোগ দেয়।

## 4. Asymptotic Notation

### 4.1 Why Do We Need These Notations?

ধরা যাক, একটি Algorithm-এর ধাপ গুনে পেলাম `f(n) = 3n + 5`। এই সঠিক সূত্রটি কি খুব কাজের? আসলে না, কারণ:

- কম্পিউটার ও গণনার পদ্ধতি বদলালে সঠিক সংখ্যাও বদলে যায়।
- n অনেক বড় হলে `+ 5` প্রায় কোনো প্রভাবই ফেলে না, আর `3` শুধু একটি Constant Factor।

আমরা আসলে জানতে চাই **Growth Pattern**: কাজ কি n-এর হারে বাড়ছে, নাকি n²-এর মতো, নাকি 2ⁿ এর মতো? **Asymptotic Notation** দিয়ে আমরা এই আকৃতি পরিষ্কারভাবে বর্ণনা করি। "Asymptotic" মানে হলো "n খুব বড় হলে কী ঘটে।"

Notation তিনটি। এগুলোকে একটি Algorithm সম্পর্কে তিন রকম প্রতিশ্রুতি ভাবতে পারেন।

| Notation | সহজ ভাষায় প্রতিশ্রুতি | ধারণা |
|---|---|---|
| **Big-O**: O | "কাজ **সর্বোচ্চ** এই সীমার মধ্যে থাকবে।" | Upper Bound |
| **Big-Omega**: Ω | "কাজ **কমপক্ষে** এই পরিমাণ হবে।" | Lower Bound |
| **Big-Theta**: Θ | "কাজ **ঠিক এই Growth Rate-এ** বাড়বে।" | Tight Bound |

### 4.2 Big-O: Upper Bound ("সর্বোচ্চ")

**ধারণা:** Big-O একটি Algorithm-এর কাজের **Upper Bound** নির্ধারণ করে। অর্থাৎ, n যথেষ্ট বড় হলে কাজের পরিমাণ নির্দিষ্ট একটি Growth Rate-এর সীমা অতিক্রম করবে না।

**দৈনন্দিন উদাহরণ:** আপনি বললেন, "সিলেট থেকে ঢাকা যেতে আমার **সর্বোচ্চ** ৮ ঘণ্টা লাগবে।" হয়তো ৫ বা ৬ ঘণ্টায়ও পৌঁছে যাবেন, কিন্তু ৮ ঘণ্টার বেশি লাগবে না। এটাই Upper Bound।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = O(g(n))` লিখি যদি এমন দুটি ধনাত্মক Constant **c** ও **n₀** পাওয়া যায় যেন

```
f(n) <= c * g(n)    সকল n >= n0 এর জন্য
```

অর্থাৎ, একটি শুরুর বিন্দু n₀ এর পর থেকে f(n) সবসময় c × g(n) এর নিচে থাকে।

**সমাধানসহ উদাহরণ:** দেখাতে হবে `f(n) = 3n + 5` হলো `O(n)`।

c ও n₀ খুঁজতে হবে। c = 4 ধরি (3 এর চেয়ে একটু বেশি):

| n | f(n) = 3n + 5 | c·g(n) = 4n | f(n) <= 4n কি? |
|---|---|---|---|
| 1 | 8 | 4 | না |
| 2 | 11 | 8 | না |
| 4 | 17 | 16 | না |
| 5 | 20 | 20 | হ্যাঁ |
| 10 | 35 | 40 | হ্যাঁ |
| 100 | 305 | 400 | হ্যাঁ |

n = 5 থেকে শুরু করে `3n + 5 <= 4n` সবসময় সত্য। তাই **n₀ = 5** ও **c = 4** কাজ করে, অতএব `3n + 5 = O(n)`।

এখান থেকে n₀ কেন দরকার তাও বোঝা যায়: খুব ছোট n-এর জন্য অসমতা মিলতে নাও পারে, কিন্তু আমরা শুধু বড় n নিয়ে ভাবি।

**গুরুত্বপূর্ণ কথা:** Big-O একটি Upper Bound, তাই আরও উঁচু Upper Bound-ও সত্য। `3n + 5` হলো `O(n)`, আবার `O(n²)` এবং `O(n³)` ও বটে, কারণ এটি ওই সীমাও পার করে না। কিন্তু এগুলো ঢিলেঢালা ও অপ্রয়োজনীয়। **আমরা সবসময় প্রমাণযোগ্য সবচেয়ে ছোট (সবচেয়ে কাছের) Upper Bound-টি বলি।**

### 4.3 Big-Omega: Lower Bound ("কমপক্ষে")

**ধারণা:** Big-Omega একটি Algorithm-এর কাজের **Lower Bound** নির্ধারণ করে। অর্থাৎ, n যথেষ্ট বড় হলে কাজের পরিমাণ নির্দিষ্ট একটি Growth Rate-এর চেয়ে কম হবে না।

**দৈনন্দিন উদাহরণ:** "যেতে আমার **কমপক্ষে** ৪ ঘণ্টা লাগবে।" রাস্তা পুরো ফাঁকা থাকলেও এর চেয়ে কম সময়ে যাওয়া সম্ভব নয়। এটাই Lower Bound।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = Ω(g(n))` লিখি যদি এমন ধনাত্মক Constant **c** ও **n₀** পাওয়া যায় যেন

```
f(n) >= c * g(n)    সকল n >= n0 এর জন্য
```

**সমাধানসহ উদাহরণ:** দেখাতে হবে `f(n) = 3n + 5` হলো `Ω(n)`।

c = 3 নিই। সকল n >= 1 এর জন্য `3n + 5 >= 3n` সত্য (কারণ 5 ধনাত্মক)। তাই **c = 3** ও **n₀ = 1** কাজ করে, অতএব `3n + 5 = Ω(n)`।

### 4.4 Big-Theta: নিখুঁত মাপ ("ঠিক এই হারে")

**ধারণা:** Big-Theta বোঝায় যে Function-টির Lower Bound ও Upper Bound একই Growth Rate-এর। তাই এটি কাজের বৃদ্ধির হারকে সবচেয়ে নির্দিষ্টভাবে প্রকাশ করে।

**দৈনন্দিন উদাহরণ:** "যেতে আমার **মোটামুটি ৬ ঘণ্টা** লাগে, সামান্য কমবেশি হতে পারে।" সময়টি দুই দিক থেকেই কাছাকাছি সীমায় আবদ্ধ।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = Θ(g(n))` লিখি যদি নিচের দুটিই সত্য হয়:

```
f(n) = O(g(n))    এবং    f(n) = Ω(g(n))
```

সমতুল্যভাবে, এমন Constant c₁, c₂ ও n₀ আছে যেন

```
c1 * g(n)  <=  f(n)  <=  c2 * g(n)    সকল n >= n0 এর জন্য
```

**সমাধানসহ উদাহরণ:** `f(n) = 3n + 5` এর জন্য আমরা আগেই `O(n)` (অনুচ্ছেদ 4.2) ও `Ω(n)` (অনুচ্ছেদ 4.3) দেখিয়েছি। দুটিই সত্য, তাই `3n + 5 = Θ(n)`।

### 4.5 A Complete Example with n²

ধরি `f(n) = 3n² + 2n + 1`। এর Big-O, Big-Omega ও Big-Theta নির্ণয় করি।

**Upper Bound।** সকল n >= 1 এর জন্য `2n <= 2n²` এবং `1 <= n²`। অতএব

```
3n² + 2n + 1  <=  3n² + 2n² + n²  =  6n²
```

সুতরাং n >= 1 এর জন্য `f(n) <= 6n²`। এতে `c = 6`, `n₀ = 1`, তাই **f(n) = O(n²)**।

**Lower Bound।** সকল n >= 1 এর জন্য `3n² + 2n + 1 >= 3n²`। এতে `c = 3`, `n₀ = 1`, তাই **f(n) = Ω(n²)**।

**Tight Bound।** দুটিই সত্য, অতএব **f(n) = Θ(n²)**।

**Shortcut:** প্রতিবার এভাবে প্রমাণ করার দরকার হয় না। শুধু সবচেয়ে বড় পদটি রাখুন এবং তার Constant বাদ দিন: `3n² + 2n + 1` থেকে হয় `n²`। অধ্যায় ৫-এ ঠিক এটাই শেখানো হয়েছে।

### 4.6 Which Statements Are True and Which Are Not?

`f(n) = 3n + 5` এর জন্য:

| বক্তব্য | সত্য? | কারণ |
|---|---|---|
| f(n) = O(n) | হ্যাঁ | কাছের Upper Bound |
| f(n) = O(n²) | হ্যাঁ | সঠিক কিন্তু ঢিলেঢালা Upper Bound |
| f(n) = O(log n) | **না** | f(n) log n-এর চেয়ে দ্রুত বাড়ে, তাই log n Upper Bound হতে পারে না |
| f(n) = Ω(n) | হ্যাঁ | কাছের Lower Bound |
| f(n) = Ω(1) | হ্যাঁ | সঠিক কিন্তু ঢিলেঢালা Lower Bound |
| f(n) = Ω(n²) | **না** | f(n) n²-এর চেয়ে ধীরে বাড়ে, তাই n² Lower Bound হতে পারে না |
| f(n) = Θ(n) | হ্যাঁ | O(n) ও Ω(n) দুটিই সত্য |
| f(n) = Θ(n²) | **না** | Ω(n²) মেলে না |

**মনে রাখার নিয়ম:** Θ(g(n)) তখনই থাকে, যখন Upper Bound ও Lower Bound উভয়ের Growth Rate একই।

### 4.7 বাস্তব Algorithm-এ প্রয়োগ: Linear Search

| পরিস্থিতি | Number of Comparisons | Notation |
|---|---|---|
| কী প্রথম অবস্থানেই আছে (Best Case) | 1 | Ω(1): অন্তত 1টি Comparison প্রয়োজন |
| কী সবশেষে আছে বা নেই (Worst Case) | n | O(n): সর্বোচ্চ nটি Comparison লাগে |
| শুধু Worst Case | n | Θ(n): Worst Case-এ ঠিক n-এর সমানুপাতিক |

অতএব Linear Search-এর জন্য বলি: সামগ্রিক চলার সময় **O(n)**, সামগ্রিকভাবে **Ω(1)**, এবং Worst Case-এ **Θ(n)**। Best ও Worst Case ভিন্ন হওয়ায় সামগ্রিক চলার সময়ের জন্য একক কোনো Θ নেই।

### 4.8 Summary ও সাধারণ বিভ্রান্তি

| Notation | সীমার ধরন | পড়ার নিয়ম |
|---|---|---|
| O(g(n)) | ঊর্ধ্ব | "সর্বোচ্চ g(n)" |
| Ω(g(n)) | নিম্ন | "কমপক্ষে g(n)" |
| Θ(g(n)) | সুনির্দিষ্ট | "ঠিক g(n) হারে বৃদ্ধি" |

- **Big-O মানেই Worst Case নয়।** Big-O হলো সীমার একটি ধরন। Worst Case হলো Input-এর একটি ধরন। Best Case-এর জন্যও Big-O বলা যায়।
- **Big-O সঠিক সময় নয়।** এটি কাজ কীভাবে বাড়ে তা বোঝায়, সেকেন্ড নয়।
- **ছোট Upper Bound মানে বেশি তথ্য।** O(n) Algorithm সম্পর্কে "এটি O(n²)" বলা সত্য, কিন্তু কাজের নয়।
- **বাস্তবে** কেউ "Time Complexity O(something)" বললে সাধারণত Worst Case-এর Big-O বোঝায়।

---

## 5. Rules for Analyzing Complexity

**নিয়ম ১: Constant Factor বাদ দিন।**
`O(5n)` হয় `O(n)`। `O(100)` হয় `O(1)`।

**নিয়ম ২: Lower-order Term বাদ দিন।**
`O(n² + n + 10)` হয় `O(n²)`। n বড় হলে সবচেয়ে বড় পদটিই প্রভাবশালী।

**নিয়ম ৩: ক্রমানুসারে থাকা অংশ যোগ হয়।**
একটি অংশের Complexity O(n) এবং পরের অংশের Complexity O(n²) হলে মোট `O(n + n²) = O(n²)`।

**নিয়ম ৪: Nested অংশ গুণ হয়।**
n বার চলা Loop-এর ভেতরে m বার চলা Loop থাকলে `O(n * m)`।

**নিয়ম ৫: ভিন্ন Input-এর জন্য ভিন্ন চলক।**
a ও b আকারের দুটি ভিন্ন Array-এর ওপর দুটি আলাদা Loop হলে `O(a + b)`, `O(n)` নয়। Nested হলে `O(a * b)`।

**নিয়ম ৬: Logarithm।**
প্রতিটি ধাপে Input-এর আকার একটি Constant দিয়ে ভাগ হলে ধাপের সংখ্যা Logarithmic হয়। Big-O-তে লগের ভিত্তি (base) উপেক্ষা করা হয়, কারণ ভিত্তি বদলালে শুধু একটি Constant Factor বদলায়।

## 6. Common Complexity Classes

দ্রুততম থেকে ধীরতম ক্রমে:

| Notation | নাম | সাধারণ উদাহরণ |
|---|---|---|
| O(1) | Constant | `a[i]` Access, Stack-এ push |
| O(log n) | Logarithmic | Binary Search |
| O(√n) | Square Root | Trial Division-এ Prime Number যাচাই |
| O(n) | Linear | Linear Search, Array-এর Element-এর যোগফল |
| O(n log n) | Linearithmic | Merge Sort, Heap Sort |
| O(n²) | Quadratic | Bubble Sort, Selection Sort, Insertion Sort |
| O(n³) | Cubic | Matrix Multiplication-এর সাধারণ পদ্ধতি |
| O(2ⁿ) | Exponential | সব Subset তৈরি করা, Naive Fibonacci |
| O(n!) | Factorial | সব Permutation |

### Comparing Growth Rates

| n | log n | n | n log n | n² | n³ | 2ⁿ | n! |
|---|---|---|---|---|---|---|---|
| 10 | 3 | 10 | 33 | 100 | 1,000 | 1,024 | 36,28,800 |
| 100 | 7 | 100 | 664 | 10,000 | 10,00,000 | 10³⁰ | 10¹⁵⁷ |
| 1,000 | 10 | 1,000 | 9,966 | 10,00,000 | 10⁹ | 10³⁰¹ | অতি বিশাল |

### Examples of Each Complexity Class

**O(1): Constant**
```cpp
int first(int a[]) {
    return a[0];            // Array-এর আকার যা-ই হোক, একটি ধাপ
}
```

**O(log n): Logarithmic**
```cpp
int binarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (a[mid] == key) return mid;
        else if (a[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```
প্রতিবার Search-এর পরিসর অর্ধেক হয়: n, n/2, n/4, ..., 1। অর্ধেক করার সংখ্যা log₂ n। n = 10,00,000 হলেও Binary Search-এ মাত্র প্রায় ২০টি ধাপ লাগে।

**O(n): Linear**
```cpp
int linearSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;
    return -1;
}
```

**O(n log n): Linearithmic**
Merge Sort Array-কে বারবার অর্ধেক করে (log n স্তর) এবং প্রতি স্তরে Merge করতে O(n) কাজ করে। বিস্তারিত অধ্যায় ১০-এ।

**O(n²): Quadratic**
```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        cout << i << j;     // n * n বার চলে
```

**O(2ⁿ): Exponential**
```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // প্রতিবার দুটি Recursive Call
}
```
প্রতিটি কল থেকে আরও দুটি কল তৈরি হয়, ফলে n এক বাড়লে কলের সংখ্যা প্রায় দ্বিগুণ হয়।

## 7. Loop Analysis

| Code Pattern | Iterations | Complexity |
|---|---|---|
| `for (i = 0; i < n; i++)` | n | O(n) |
| `for (i = 0; i < n; i += 2)` | n/2 | O(n) |
| `for (i = 1; i < n; i *= 2)` | log₂ n | O(log n) |
| `for (i = n; i > 1; i /= 2)` | log₂ n | O(log n) |
| `for (i = 0; i * i < n; i++)` | √n | O(√n) |
| দুটি Nested Loop, প্রতিটি n পর্যন্ত | n × n | O(n²) |
| বাইরের Loop n পর্যন্ত, ভেতরে `j *= 2` | n × log n | O(n log n) |
| পরপর দুটি Loop | n + n | O(n) |

### Dependent Nested Loop

```cpp
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= i; j++)
        count++;
```

Inner Loop চলে 1, 2, 3, ..., n বার। মোট:

```
1 + 2 + 3 + ... + n = n(n + 1) / 2 = (n² + n) / 2
```

Constant ও Lower-order Term বাদ দিলে **O(n²)**।

### Example with a Multiplicative Inner Loop

```cpp
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        count++;
```

Outer Loop n বার এবং Inner Loop log n বার চলে। মোট **O(n log n)**।

## 8. Best, Worst, and Average Cases

অনেক Algorithm-এর চলার সময় শুধু Input Size-এর ওপর নয়, Input-এর **Arrangement**-এর ওপরও নির্ভর করে।

n Element-এর Array-তে Linear Search-এর উদাহরণ:

| কেস | পরিস্থিতি | Comparison-এর সংখ্যা | Complexity |
|---|---|---|---|
| **Best Case** | কী প্রথম Element-এই আছে | 1 | O(1) |
| **Worst Case** | কী সবশেষে আছে বা নেই | n | O(n) |
| **Average Case** | কী যেকোনো স্থানে থাকার সম্ভাবনা সমান | প্রায় n/2 | O(n) |

- **Worst Case** একটি নিশ্চয়তা দেয়: Algorithm এর চেয়ে ধীর হবে না। এটিই সবচেয়ে বেশি ব্যবহৃত হয়।
- **Best Case** খুব আশাবাদী, তাই কম কাজে লাগে।
- **Average Case** কাজের, কিন্তু Input-এর বণ্টন সম্পর্কে অনুমান প্রয়োজন।

**গুরুত্বপূর্ণ:** Best, Worst, Average হলো Input-এর *কেস*। Big-O, Omega, Theta হলো সীমার *Notation*। এ দুটি আলাদা ধারণা। যেমন বলা যায়, "Linear Search-এর Worst Case Θ(n)।"

**উদাহরণ: Quick Sort।** Average Case O(n log n), Worst Case O(n²) (যখন Pivot সবসময় সবচেয়ে ছোট বা সবচেয়ে বড় Element হয়)।

## 9. Space Complexity

**Space Complexity** হলো n-এর Function হিসেবে Algorithm-এর প্রয়োজনীয় অতিরিক্ত Memory।

```
মোট Space = Input Space + Auxiliary Space
```

- **Input Space:** Input নিজে যে Memory ব্যবহার করে।
- **Auxiliary Space:** Algorithm-এর অতিরিক্ত Memory usage (যেমন: temporary variable, অতিরিক্ত Array এবং Recursion Stack)।

সাধারণত "Space Complexity" বলতে **Auxiliary Space** বোঝানো হয়।

### উদাহরণ

**O(1) Space:**
```cpp
int sum(int a[], int n) {
    int s = 0;                 // কয়েকটি Variable মাত্র, n-এর ওপর নির্ভর করে না
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}
```

**O(n) Space:**
```cpp
int* copyArray(int a[], int n) {
    int* b = new int[n];       // n আকারের অতিরিক্ত Array
    for (int i = 0; i < n; i++) b[i] = a[i];
    return b;
}
```

**O(n²) Space:** n × n আকারের Matrix তৈরি করা।

### Recursion ও Space

প্রতিটি Recursive Call **Call Stack-এ** জমা থাকে। Recursion n স্তর গভীর হলে কোনো Array না বানালেও O(n) Space লাগে।

```cpp
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```
Time Complexity: O(n)। Space Complexity: **O(n)**, কারণ সবচেয়ে গভীর অবস্থায় Call Stack-এ nটি Stack Frame তৈরি হয়।

একই Function-এর Iterative সংস্করণে Space লাগে **O(1)**।

### Auxiliary Space of Common Algorithms

| Algorithm | Auxiliary Space |
|---|---|
| Bubble Sort, Selection Sort, Insertion Sort | O(1) |
| Merge Sort | O(n) |
| Quick Sort (Average) | O(log n) Stack |
| Heap Sort | O(1) |
| Binary Search (Iterative) | O(1) |
| Binary Search (Recursive) | O(log n) |
| V টি Vertex-এর Graph-এ DFS / BFS | O(V) |

## 10. Recursive Algorithm Analysis

Recursive Algorithm-এর জন্য আমরা একটি **Recurrence Relation** লিখি: এটি এমন একটি সমীকরণ, যা ছোট Input-এর জন্য প্রয়োজনীয় running time ব্যবহার করে T(n) প্রকাশ করে।

### 10.1 Examples of Recurrences

| Algorithm | Recurrence | সমাধান |
|---|---|---|
| Factorial | T(n) = T(n-1) + O(1) | O(n) |
| Binary Search | T(n) = T(n/2) + O(1) | O(log n) |
| Merge Sort | T(n) = 2T(n/2) + O(n) | O(n log n) |
| Naive Fibonacci | T(n) = T(n-1) + T(n-2) + O(1) | O(2ⁿ) |
| Tower of Hanoi | T(n) = 2T(n-1) + O(1) | O(2ⁿ) |

### 10.2 Method 1: Substitution (Unrolling)

T(n) = T(n-1) + 1 সমাধান করি, যেখানে T(0) = 1।

```
T(n) = T(n-1) + 1
     = T(n-2) + 1 + 1
     = T(n-3) + 1 + 1 + 1
     ...
     = T(0) + n
     = n + 1          ->  O(n)
```

### 10.3 Method 2: Recursion Tree (Merge Sort)

T(n) = 2T(n/2) + n

```
Level 0:   n                          -> মোট কাজ n
Level 1:   n/2   n/2                  -> মোট কাজ n
Level 2:   n/4 n/4 n/4 n/4            -> মোট কাজ n
...
Level k:   2^k টি Node, প্রতিটি n/2^k  -> মোট কাজ n
```

Recursion Tree-তে **log₂ n টি Level** আছে এবং প্রতি Level-এ **n** পরিমাণ কাজ হয়। মোট = **O(n log n)**।

### 10.4 Method 3: Master Theorem (সরলীকৃত)

নিচের Form-এর Recurrence-এর জন্য

```
T(n) = a * T(n / b) + O(n^d)       যেখানে a >= 1, b > 1, d >= 0
```

| শর্ত | ফলাফল |
|---|---|
| a < bᵈ | T(n) = O(nᵈ) |
| a = bᵈ | T(n) = O(nᵈ log n) |
| a > bᵈ | T(n) = O(n^(log_b a)) |

**উদাহরণ:**

- Merge Sort: a = 2, b = 2, d = 1। এখানে a = bᵈ (2 = 2), তাই T(n) = **O(n log n)**।
- Binary Search: a = 1, b = 2, d = 0। এখানে a = bᵈ (1 = 1), তাই T(n) = **O(log n)**।
- T(n) = 4T(n/2) + n: a = 4, b = 2, d = 1। এখানে a > bᵈ (4 > 2), তাই T(n) = O(n^(log₂ 4)) = **O(n²)**।
- T(n) = T(n/2) + n: a = 1, b = 2, d = 1। এখানে a < bᵈ (1 < 2), তাই T(n) = **O(n)**।

**মনে রাখুন:** T(n) = T(n-1) + T(n-2) এর মতো Recurrence-এ Master Theorem প্রযোজ্য নয়। সেক্ষেত্রে Recursion Tree বা Unrolling ব্যবহার করুন।

## 11. Amortized Analysis

কখনো কখনো একটি Operation মাঝেমধ্যে ব্যয়বহুল হয়, কিন্তু বেশিরভাগ Operation সস্তা। **Amortized Analysis** Operation-এর একটি ধারার ওপর **প্রতি Operation-এর Average Cost** দেয়, এতে কোনো সম্ভাবনা ব্যবহার করা হয় না।

### উদাহরণ: Dynamic Array (C++-এর `vector`)

Array ভরে গেলে **দ্বিগুণ** আকারের নতুন Array তৈরি হয় এবং সব Element Copy করা হয়।

- বেশিরভাগ `push_back`-এর খরচ O(1)।
- মাঝেমধ্যে একটির খরচ O(n), কারণ Copy করতে হয়।

nটি Insertion-এর সময় Capacity 1, 2, 4, 8, ..., n হওয়ার পর্যায়ে Element Copy হয়। মোট Copy Operations:

```
1 + 2 + 4 + ... + n  <  2n
```

nটি Insertion-এর মোট খরচ 3n-এর কম, অতএব **প্রতি Insertion-এর Amortized Cost হলো O(1)**।

**Average Case-এর সঙ্গে পার্থক্য:** Amortized Analysis হলো Operation-এর ধারার ওপর Worst Case-এর নিশ্চয়তা। Average Case নির্ভর করে Input সম্পর্কে সম্ভাবনার অনুমানের ওপর।

## 12. Time-Space Trade-off

প্রায়ই বেশি Memory ব্যবহার করে Algorithm দ্রুত করা যায়, অথবা ধীর গতি মেনে নিয়ে Memory বাঁচানো যায়।

**উদাহরণ: Fibonacci**

| পদ্ধতি | Time | Space |
|---|---|---|
| Naive Recursion | O(2ⁿ) | O(n) |
| Memoization (হিসাব করা ফলাফল Array-তে রাখা) | O(n) | O(n) |
| দুটি Variable ব্যবহার করে Iterative পদ্ধতি | O(n) | O(1) |

**উদাহরণ: Array-তে Duplicate যাচাই**

| পদ্ধতি | Time | Space |
|---|---|---|
| প্রতিটি জোড়া Comparison | O(n²) | O(1) |
| আগে Sort, তারপর পাশাপাশি যাচাই | O(n log n) | O(1) বা O(n) |
| Hash Set ব্যবহার | O(n) Average | O(n) |

সব ক্ষেত্রে সেরা কোনো একক পছন্দ নেই। সমস্যার Constraint-এর ওপর সঠিক পছন্দ নির্ভর করে।

| Merge Sort | O(n log n) | O(n log n) | O(n log n) | O(n) | হ্যাঁ |
| Quick Sort | O(n log n) | O(n log n) | O(n²) | O(log n) | না |
| Heap Sort | O(n log n) | O(n log n) | O(n log n) | O(1) | না |

Bubble Sort-এর Best Case O(n) হয় শুধু তখনই, যখন এতে আগে থেমে যাওয়ার Flag থাকে। Binary Search-এর জন্য Array Sorted হওয়া আবশ্যক।

**তথ্য:** Comparison-based যেকোনো Sorting Algorithm-এর Worst Case-এ কমপক্ষে Ω(n log n) Comparison লাগে। তাই Merge Sort ও Heap Sort Comparison-based Sort-এর মধ্যে Optimal।

## 14. Choosing an Algorithm Based on Constraints

একটি সাধারণ Computer প্রতি সেকেন্ডে প্রায় **10⁸টি Simple Operation** করতে পারে। Time Limit ১ সেকেন্ড হলে Input Size n দেখে বুঝে নিন কোন Complexity গ্রহণযোগ্য:

| Input Size n | গ্রহণযোগ্য Complexity |
|---|---|
| n <= 10 | O(n!) |
| n <= 20 | O(2ⁿ) |
| n <= 500 | O(n³) |
| n <= 5,000 | O(n²) |
| n <= 10⁶ | O(n log n) |
| n <= 10⁸ | O(n) |
| n > 10⁸ | O(log n) অথবা O(1) |

n = 1,00,000 হলে O(n²) সমাধানে 10¹⁰ Operation লাগে, যা অনেক ধীর। O(n log n) সমাধানে লাগে প্রায় ১৭ লাখ Operation, যা মুহূর্তেই শেষ হয়।

## 15. Common Mistakes

1. **Case ও Notation গুলিয়ে ফেলা।** Worst Case আর Big-O এক জিনিস নয় (অধ্যায় ৮ দেখুন)।
2. **লুকানো খরচ উপেক্ষা করা।** String-এ `s = s + str` এর মতো একটি লাইনেও Copy করার কারণে O(n) খরচ হতে পারে।
3. **একটি Loop মানেই O(n) ধরে নেওয়া।** Loop Variable-টি কীভাবে বদলায় তা দেখুন। `i *= 2` হলে O(log n)।
4. **Recursion Stack-এর Space ভুলে যাওয়া।** n গভীরতার Recursive Function O(n) Memory নেয়।
5. **শুধু একটি Input Size ধরা।** দুটি Input থাকলে (যেমন a ও b আকারের দুটি Array) দুটি চলকই ব্যবহার করুন।
6. **Big-O কে সঠিক সময় ভাবা।** Big-O Growth Rate বোঝায়, সেকেন্ড নয়। বিশাল Constant-সহ O(n) Algorithm বাস্তবে ছোট Input-এ O(n log n) Algorithm-এর চেয়ে ধীর হতে পারে।

## 16. Introduction to P and NP

এটি একটি Advanced Topic; এখানে শুধু প্রাথমিক ধারণা দেওয়া হয়েছে।

- **Class P:** যেসব সমস্যা Polynomial Time-এ (O(n), O(n²), O(n³) ইত্যাদি) **সমাধান** করা যায়। উদাহরণ: Sorting, Searching, Shortest Path।
- **Class NP:** যেসব Problem-এর কোনো proposed solution Polynomial Time-এ **verify** করা যায়। P-এর প্রতিটি Problem-ই NP-এর অন্তর্গত।
- **NP-complete:** NP-এর সবচেয়ে কঠিন Problem-গুলো। এদের যেকোনো একটি Polynomial Time-এ সমাধান করা গেলে সবগুলোই করা যাবে। উদাহরণ: Traveling Salesperson Problem (Decision Version), Subset Sum, Boolean Satisfiability (SAT)।

**P = NP কি না** তা Computer Science-এর সবচেয়ে বড় অমীমাংসিত সমস্যাগুলোর একটি। NP-complete সমস্যার জন্য বর্তমানে কোনো Polynomial Time-এর Algorithm জানা নেই, তাই বাস্তবে অনেক ক্ষেত্রে Approximation বা Heuristic পদ্ধতি ব্যবহার করা হয়।

## 17. Practice Problems

নিচের প্রতিটি কোডের Time Complexity নির্ণয় করুন।

**সমস্যা ১**

```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < 100; j++)
        x++;
```

**সমস্যা ২**

```cpp
for (int i = n; i >= 1; i /= 2)
    x++;
```

**সমস্যা ৩**
```cpp
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        x++;
```

**সমস্যা ৪**

```cpp
for (int i = 0; i < n; i++)
    x++;
for (int j = 0; j < m; j++)
    y++;
```

**সমস্যা ৫**
```cpp
void f(int n) {
    if (n <= 1) return;
    f(n / 2);
    f(n / 2);
    for (int i = 0; i < n; i++) x++;
}
```

**সমস্যা ৬**
n Element-এর Array-তে Recursive Binary Search-এর Space Complexity কত?

### Answers

1. **O(n)।** ভেতরের Loop Constant ১০০ বার চলে। মোট 100n, অতএব O(n)।
2. **O(log n)।** প্রতিবার i এর মান অর্ধেক হয়।
3. **O(n²)।** ভেতরের Loop চলে n, n-1, ..., 1 বার। মোট n(n+1)/2।
4. **O(n + m)।** Loop দুটি পরপর এবং ভিন্ন চলক ব্যবহার করে।
5. **O(n log n)।** Recurrence T(n) = 2T(n/2) + n, Merge Sort-এর মতোই।
6. **O(log n)।** Recursion-এর গভীরতা log₂ n এবং প্রতি Recursion Level-এ O(1) Space লাগে।

## 18. Summary

- Complexity মাপে Input Size n-এর সাথে সময় ও Memory কীভাবে **বাড়ে**, সঠিক সেকেন্ড নয়।
- **Big-O** Upper Bound, **Big-Omega** Lower Bound এবং **Big-Theta** Tight Bound বোঝায়।
- Constant ও Lower-order Term বাদ দিন। পরপর থাকা অংশ যোগ করুন। Nested অংশ গুণ করুন।
- বৃদ্ধির ক্রম: `1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!`
- Loop-এ অর্ধেক বা দ্বিগুণ করলে **log n** হয়।
- Recursion-এ **Stack Space** লাগে। Recurrence, Recursion Tree বা Master Theorem দিয়ে Recursion বিশ্লেষণ করুন।
- **Amortized Analysis** Operation-এর ধারার প্রকৃত Average Cost দেয়।
- দ্রুত Algorithm-এ প্রায়ই বেশি Memory লাগে (**Time-Space Trade-off**)।
- Input-এর Constraint দেখে গ্রহণযোগ্য Complexity ঠিক করুন।
