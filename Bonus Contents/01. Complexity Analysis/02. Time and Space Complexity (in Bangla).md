## 1. কমপ্লেক্সিটি কেন গুরুত্বপূর্ণ

একটি সমস্যা অনেক ভিন্ন উপায়ে সমাধান করা যায়। যেমন, দশ লাখ নামের একটি তালিকা থেকে একটি নাম খুঁজে বের করতে প্রতিটি নাম একে একে দেখা যায়, আবার অনেক বুদ্ধিমান পদ্ধতিও ব্যবহার করা যায়। দুটি পদ্ধতিই সঠিক উত্তর দেবে, কিন্তু একটি চোখের পলকে শেষ হতে পারে, আরেকটিতে কয়েক মিনিট লাগতে পারে।

**কমপ্লেক্সিটি বিশ্লেষণ** হলো এমন একটি পদ্ধতি, যার মাধ্যমে আমরা কোনো অ্যালগরিদম চালানোর **আগেই** তার কার্যকারিতা পরিমাপ করতে এবং একাধিক অ্যালগরিদমের মধ্যে তুলনা করতে পারি।

আমরা দুটি বিষয় পরিমাপ করি:

| পরিমাপ | যে প্রশ্নের উত্তর দেয় |
|---|---|
| **টাইম কমপ্লেক্সিটি** | ইনপুট বাড়লে চলার সময় কত দ্রুত বাড়ে? |
| **স্পেস কমপ্লেক্সিটি** | ইনপুট বাড়লে মেমরির ব্যবহার কত দ্রুত বাড়ে? |

**স্টপওয়াচ দিয়ে সেকেন্ড মাপলেই কেন হয় না?** কারণ ফলাফল নির্ভর করে কম্পিউটারের গতি, প্রোগ্রামিং ল্যাঙ্গুয়েজ, কম্পাইলার এবং তখন আর কী চলছে তার ওপর। ধীর কম্পিউটারে দ্রুত অ্যালগরিদমকে খারাপ মনে হতে পারে। তাই আমাদের এমন একটি পরিমাপ দরকার যা মেশিনের ওপর নির্ভর করে না।

## 2. ইনপুট সাইজ ও ধাপ গণনা

ধারণাটি সহজ:

- ইনপুটের আকারকে ধরি **n** (অ্যারের এলিমেন্ট সংখ্যা, লিংকড লিস্টের নোড সংখ্যা, কোনো সংখ্যার ডিজিট সংখ্যা ইত্যাদি)।
- অ্যালগরিদমটি n এর ওপর নির্ভর করে মোট কতগুলো **মৌলিক অপারেশন** করে তা গণনা করি। তুলনা, অ্যাসাইনমেন্ট, গাণিতিক অপারেশন, অ্যারের এলিমেন্ট অ্যাক্সেস হলো মৌলিক অপারেশন।
- n খুব বড় হলে এই গণনা কীভাবে **বাড়ে**, সেটিই আমরা দেখি।

**উদাহরণ:** অ্যারের সব এলিমেন্টের যোগফল।

```cpp
int sum = 0;                    // 1টি অপারেশন
for (int i = 0; i < n; i++) {   // লুপ n বার চলে
    sum += a[i];                // প্রতিবার 1টি অপারেশন
}
return sum;                     // 1টি অপারেশন
```

মোট অপারেশন প্রায় `n + 2`। n = 10,00,000 হলে কাজ প্রায় দশ লাখ ধাপ। n এর তুলনায় "+ 2" নগণ্য। এই পর্যবেক্ষণ থেকেই অ্যাসিম্পটোটিক নোটেশনের ধারণা এসেছে।

## 3. টাইম কমপ্লেক্সিটি

**টাইম কমপ্লেক্সিটি** হলো ইনপুট সাইজ n এর একটি ফাংশন হিসেবে অ্যালগরিদমের মৌলিক অপারেশনের সংখ্যা।

তিনটি ভিন্ন অ্যালগরিদমের ধাপ সংখ্যার ফাংশন তুলনা করা যাক:

| n | অ্যালগরিদম A: 5n | অ্যালগরিদম B: n² | অ্যালগরিদম C: 2ⁿ |
|---|---|---|---|
| 10 | 50 | 100 | 1,024 |
| 100 | 500 | 10,000 | 1.27 × 10³⁰ |
| 1,000 | 5,000 | 10,00,000 | অকল্পনীয়ভাবে বিশাল |

n ছোট হলে পার্থক্য বোঝা কঠিন। n বড় হলে পার্থক্য বিশাল। কমপ্লেক্সিটি বিশ্লেষণ বড় n এর জন্য এই **বৃদ্ধির হারের** ওপর মনোযোগ দেয়।

## 4. অ্যাসিম্পটোটিক নোটেশন

### 4.1 এই নোটেশনগুলো কোন সমস্যার সমাধান করে

ধরা যাক, একটি অ্যালগরিদমের ধাপ গুনে পেলাম `f(n) = 3n + 5`। এই সঠিক সূত্রটি কি খুব কাজের? আসলে না, কারণ:

- কম্পিউটার ও গণনার পদ্ধতি বদলালে সঠিক সংখ্যাও বদলে যায়।
- n অনেক বড় হলে `+ 5` প্রায় কোনো প্রভাবই ফেলে না, আর `3` শুধু একটি ধ্রুবক গুণক।

আমরা আসলে জানতে চাই **বৃদ্ধির আকৃতি**: কাজ কি n এর মতো বাড়ছে, নাকি n² এর মতো, নাকি 2ⁿ এর মতো? **অ্যাসিম্পটোটিক নোটেশন** দিয়ে আমরা এই আকৃতি পরিষ্কারভাবে বর্ণনা করি। "অ্যাসিম্পটোটিক" মানে হলো "n খুব বড় হলে কী ঘটে।"

নোটেশন তিনটি। এগুলোকে একটি অ্যালগরিদম সম্পর্কে তিন রকম প্রতিশ্রুতি ভাবতে পারেন।

| নোটেশন | সহজ ভাষায় প্রতিশ্রুতি | ধারণা |
|---|---|---|
| **বিগ-ও**: O | "কাজ **সর্বোচ্চ** এতটুকু লাগবে।" | ঊর্ধ্বসীমা (ছাদ) |
| **বিগ-ওমেগা**: Ω | "কাজ **কমপক্ষে** এতটুকু লাগবে।" | নিম্নসীমা (মেঝে) |
| **বিগ-থেটা**: Θ | "কাজ **ঠিক** এই হারে লাগবে।" | সুনির্দিষ্ট সীমা (দুটোই) |

### 4.2 বিগ-ও: ছাদ ("সর্বোচ্চ")

**ধারণা:** বিগ-ও বলে, অ্যালগরিদমটি একটি নির্দিষ্ট বৃদ্ধির হারের চেয়ে **কখনোই খারাপ হবে না**।

**দৈনন্দিন উদাহরণ:** আপনি বললেন, "সিলেট থেকে ঢাকা যেতে আমার **সর্বোচ্চ** ৮ ঘণ্টা লাগবে।" হয়তো ৫ বা ৬ ঘণ্টায়ও পৌঁছে যাবেন, কিন্তু ৮ ঘণ্টার বেশি লাগবে না। এটাই ছাদ।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = O(g(n))` লিখি যদি এমন দুটি ধনাত্মক ধ্রুবক **c** ও **n₀** পাওয়া যায় যেন

```
f(n) <= c * g(n)    সকল n >= n0 এর জন্য
```

অর্থাৎ, একটি শুরুর বিন্দু n₀ এর পর থেকে f(n) সবসময় c × g(n) এর নিচে থাকে।

**সমাধানসহ উদাহরণ:** দেখাতে হবে `f(n) = 3n + 5` হলো `O(n)`।

c ও n₀ খুঁজতে হবে। c = 4 ধরি (3 এর চেয়ে একটু বেশি):

| n | f(n) = 3n + 5 | c·g(n) = 4n | f(n) <= 4n কি? |
|---|---|---|---|
| 1 | 8 | 4 | না |
| 2 | 11 | 8 | না |
| 4 | 17 | 16 | না |
| 5 | 20 | 20 | হ্যাঁ |
| 10 | 35 | 40 | হ্যাঁ |
| 100 | 305 | 400 | হ্যাঁ |

n = 5 থেকে শুরু করে `3n + 5 <= 4n` সবসময় সত্য। তাই **n₀ = 5** ও **c = 4** কাজ করে, অতএব `3n + 5 = O(n)`।

এখান থেকে n₀ কেন দরকার তাও বোঝা যায়: খুব ছোট n এর জন্য অসমতা মিলতে নাও পারে, কিন্তু আমরা শুধু বড় n নিয়ে ভাবি।

**গুরুত্বপূর্ণ কথা:** বিগ-ও একটি ছাদ, তাই আরও উঁচু ছাদও সত্য। `3n + 5` হলো `O(n)`, আবার `O(n²)` এবং `O(n³)` ও বটে, কারণ এটি ওই সীমাও পার করে না। কিন্তু এগুলো ঢিলেঢালা ও অপ্রয়োজনীয়। **আমরা সবসময় প্রমাণযোগ্য সবচেয়ে ছোট (সবচেয়ে কাছের) ছাদটি বলি।**

### 4.3 বিগ-ওমেগা: মেঝে ("কমপক্ষে")

**ধারণা:** বিগ-ওমেগা বলে, অ্যালগরিদমটি একটি নির্দিষ্ট বৃদ্ধির হারের চেয়ে **কখনোই ভালো হবে না**।

**দৈনন্দিন উদাহরণ:** "যেতে আমার **কমপক্ষে** ৪ ঘণ্টা লাগবে।" রাস্তা পুরো ফাঁকা থাকলেও এর চেয়ে কম সময়ে যাওয়া সম্ভব নয়। এটাই মেঝে।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = Ω(g(n))` লিখি যদি এমন ধনাত্মক ধ্রুবক **c** ও **n₀** পাওয়া যায় যেন

```
f(n) >= c * g(n)    সকল n >= n0 এর জন্য
```

**সমাধানসহ উদাহরণ:** দেখাতে হবে `f(n) = 3n + 5` হলো `Ω(n)`।

c = 3 নিই। সকল n >= 1 এর জন্য `3n + 5 >= 3n` সত্য (কারণ 5 ধনাত্মক)। তাই **c = 3** ও **n₀ = 1** কাজ করে, অতএব `3n + 5 = Ω(n)`।

### 4.4 বিগ-থেটা: নিখুঁত মাপ ("ঠিক এই হারে")

**ধারণা:** বিগ-থেটা বলে, ফাংশনটি **একই বৃদ্ধির হারের** একটি মেঝে ও একটি ছাদের মাঝখানে চেপে আছে। এটি সবচেয়ে নিখুঁত বক্তব্য।

**দৈনন্দিন উদাহরণ:** "যেতে আমার **মোটামুটি ৬ ঘণ্টা** লাগে, সামান্য কমবেশি হতে পারে।" সময়টি দুই দিক থেকেই কাছাকাছি সীমায় আবদ্ধ।

**আনুষ্ঠানিক সংজ্ঞা:** `f(n) = Θ(g(n))` লিখি যদি নিচের দুটিই সত্য হয়:

```
f(n) = O(g(n))    এবং    f(n) = Ω(g(n))
```

সমতুল্যভাবে, এমন ধ্রুবক c₁, c₂ ও n₀ আছে যেন

```
c1 * g(n)  <=  f(n)  <=  c2 * g(n)    সকল n >= n0 এর জন্য
```

**সমাধানসহ উদাহরণ:** `f(n) = 3n + 5` এর জন্য আমরা আগেই `O(n)` (অনুচ্ছেদ 4.2) ও `Ω(n)` (অনুচ্ছেদ 4.3) দেখিয়েছি। দুটিই সত্য, তাই `3n + 5 = Θ(n)`।

### 4.5 n² নিয়ে একটি পূর্ণাঙ্গ উদাহরণ

ধরি `f(n) = 3n² + 2n + 1`। এর O, Ω ও Θ নির্ণয় করি।

**ঊর্ধ্বসীমা।** সকল n >= 1 এর জন্য `2n <= 2n²` এবং `1 <= n²`। অতএব

```
3n² + 2n + 1  <=  3n² + 2n² + n²  =  6n²
```

সুতরাং n >= 1 এর জন্য `f(n) <= 6n²`। এতে `c = 6`, `n₀ = 1`, তাই **f(n) = O(n²)**।

**নিম্নসীমা।** সকল n >= 1 এর জন্য `3n² + 2n + 1 >= 3n²`। এতে `c = 3`, `n₀ = 1`, তাই **f(n) = Ω(n²)**।

**সুনির্দিষ্ট সীমা।** দুটিই সত্য, অতএব **f(n) = Θ(n²)**।

**শর্টকাট:** প্রতিবার এভাবে প্রমাণ করার দরকার হয় না। শুধু সবচেয়ে বড় পদটি রাখুন এবং তার ধ্রুবক বাদ দিন: `3n² + 2n + 1` থেকে হয় `n²`। অধ্যায় ৫ এ ঠিক এটাই শেখানো হয়েছে।

### 4.6 কোনটি সত্য এবং কোনটি নয়

`f(n) = 3n + 5` এর জন্য:

| বক্তব্য | সত্য? | কারণ |
|---|---|---|
| f(n) = O(n) | হ্যাঁ | কাছের ছাদ |
| f(n) = O(n²) | হ্যাঁ | সঠিক কিন্তু ঢিলেঢালা ছাদ |
| f(n) = O(log n) | **না** | f(n) log n এর চেয়ে দ্রুত বাড়ে, তাই log n ছাদ হতে পারে না |
| f(n) = Ω(n) | হ্যাঁ | কাছের মেঝে |
| f(n) = Ω(1) | হ্যাঁ | সঠিক কিন্তু ঢিলেঢালা মেঝে |
| f(n) = Ω(n²) | **না** | f(n) n² এর চেয়ে ধীরে বাড়ে, তাই n² মেঝে হতে পারে না |
| f(n) = Θ(n) | হ্যাঁ | O(n) ও Ω(n) দুটিই সত্য |
| f(n) = Θ(n²) | **না** | Ω(n²) মেলে না |

**মনে রাখার নিয়ম:** Θ(g(n)) তখনই থাকে, যখন ছাদ ও মেঝে উভয়ের বৃদ্ধির হার একই।

### 4.7 বাস্তব অ্যালগরিদমে প্রয়োগ: লিনিয়ার সার্চ

| পরিস্থিতি | ধাপ | নোটেশন |
|---|---|---|
| কী প্রথম অবস্থানেই আছে (বেস্ট কেস) | 1 | Ω(1): অ্যালগরিদম একটি তুলনার কমে কখনো পারে না |
| কী সবশেষে আছে বা নেই (ওয়ার্স্ট কেস) | n | O(n): n টির বেশি তুলনা কখনো লাগে না |
| শুধু ওয়ার্স্ট কেস | n | Θ(n): ওয়ার্স্ট কেসে ঠিক n এর সমানুপাতিক |

অতএব লিনিয়ার সার্চের জন্য বলি: সামগ্রিক চলার সময় **O(n)**, সামগ্রিকভাবে **Ω(1)**, এবং ওয়ার্স্ট কেসে **Θ(n)**। বেস্ট ও ওয়ার্স্ট কেস ভিন্ন হওয়ায় সামগ্রিক চলার সময়ের জন্য একক কোনো Θ নেই।

### 4.8 সারসংক্ষেপ ও সাধারণ বিভ্রান্তি

| নোটেশন | সীমার ধরন | পড়ার নিয়ম |
|---|---|---|
| O(g(n)) | ঊর্ধ্ব | "সর্বোচ্চ g(n)" |
| Ω(g(n)) | নিম্ন | "কমপক্ষে g(n)" |
| Θ(g(n)) | সুনির্দিষ্ট | "ঠিক g(n) হারে বৃদ্ধি" |

- **বিগ-ও মানেই ওয়ার্স্ট কেস নয়।** বিগ-ও হলো সীমার একটি ধরন। ওয়ার্স্ট কেস হলো ইনপুটের একটি ধরন। বেস্ট কেসের জন্যও বিগ-ও বলা যায়।
- **বিগ-ও সঠিক সময় নয়।** এটি কাজ কীভাবে বাড়ে তা বোঝায়, সেকেন্ড নয়।
- **ছোট ছাদ মানে বেশি তথ্য।** O(n) অ্যালগরিদম সম্পর্কে "এটি O(n²)" বলা সত্য, কিন্তু কাজের নয়।
- **বাস্তবে** কেউ "টাইম কমপ্লেক্সিটি O(কিছু একটা)" বললে সাধারণত ওয়ার্স্ট কেসের বিগ-ও বোঝায়।

## 5. কমপ্লেক্সিটি নির্ণয়ের নিয়ম

**নিয়ম ১: ধ্রুবক গুণক বাদ দিন।**
`O(5n)` হয় `O(n)`। `O(100)` হয় `O(1)`।

**নিয়ম ২: নিম্নমানের পদ বাদ দিন।**
`O(n² + n + 10)` হয় `O(n²)`। n বড় হলে সবচেয়ে বড় পদটিই প্রভাবশালী।

**নিয়ম ৩: ক্রমানুসারে থাকা অংশ যোগ হয়।**
একটি অংশ O(n) এবং পরের অংশ O(n²) হলে মোট `O(n + n²) = O(n²)`।

**নিয়ম ৪: নেস্টেড অংশ গুণ হয়।**
n বার চলা লুপের ভেতরে m বার চলা লুপ থাকলে `O(n * m)`।

**নিয়ম ৫: ভিন্ন ইনপুটের জন্য ভিন্ন চলক।**
a ও b আকারের দুটি ভিন্ন অ্যারের ওপর দুটি আলাদা লুপ হলে `O(a + b)`, `O(n)` নয়। নেস্টেড হলে `O(a * b)`।

**নিয়ম ৬: লগারিদম।**
প্রতি ধাপে সমস্যার আকার একটি ধ্রুবক দিয়ে ভাগ হলে ধাপের সংখ্যা লগারিদমিক হয়। বিগ-ও তে লগের ভিত্তি (base) উপেক্ষা করা হয়, কারণ ভিত্তি বদলালে শুধু একটি ধ্রুবক গুণক বদলায়।

## 6. প্রচলিত কমপ্লেক্সিটি শ্রেণি

দ্রুততম থেকে ধীরতম ক্রমে:

| নোটেশন | নাম | সাধারণ উদাহরণ |
|---|---|---|
| O(1) | কনস্ট্যান্ট | `a[i]` অ্যাক্সেস, স্ট্যাকে push |
| O(log n) | লগারিদমিক | বাইনারি সার্চ |
| O(√n) | স্কয়ার রুট | ট্রায়াল ডিভিশনে মৌলিক সংখ্যা যাচাই |
| O(n) | লিনিয়ার | লিনিয়ার সার্চ, অ্যারের যোগফল |
| O(n log n) | লিনিয়ারিদমিক | মার্জ সর্ট, হিপ সর্ট |
| O(n²) | কোয়াড্রাটিক | বাবল সর্ট, সিলেকশন সর্ট, ইনসারশন সর্ট |
| O(n³) | কিউবিক | ম্যাট্রিক্স গুণনের সাধারণ পদ্ধতি |
| O(2ⁿ) | এক্সপোনেনশিয়াল | সব সাবসেট, নাইভ ফিবোনাচ্চি |
| O(n!) | ফ্যাক্টোরিয়াল | সব পারমুটেশন |

### বৃদ্ধির তুলনা

| n | log n | n | n log n | n² | n³ | 2ⁿ | n! |
|---|---|---|---|---|---|---|---|
| 10 | 3 | 10 | 33 | 100 | 1,000 | 1,024 | 36,28,800 |
| 100 | 7 | 100 | 664 | 10,000 | 10,00,000 | 10³⁰ | 10¹⁵⁷ |
| 1,000 | 10 | 1,000 | 9,966 | 10,00,000 | 10⁹ | 10³⁰¹ | অতি বিশাল |

### প্রতিটি শ্রেণির উদাহরণ

**O(1): কনস্ট্যান্ট**
```cpp
int first(int a[]) {
    return a[0];            // অ্যারের আকার যা-ই হোক, একটি ধাপ
}
```

**O(log n): লগারিদমিক**
```cpp
int binarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (a[mid] == key) return mid;
        else if (a[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```
প্রতিবার সার্চের পরিসর অর্ধেক হয়: n, n/2, n/4, ..., 1। অর্ধেক করার সংখ্যা log₂ n। n = 10,00,000 হলেও বাইনারি সার্চে মাত্র প্রায় ২০টি ধাপ লাগে।

**O(n): লিনিয়ার**
```cpp
int linearSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;
    return -1;
}
```

**O(n log n): লিনিয়ারিদমিক**
মার্জ সর্ট অ্যারেকে বারবার অর্ধেক করে (log n স্তর) এবং প্রতি স্তরে মার্জ করতে O(n) কাজ করে। বিস্তারিত অধ্যায় ১০ এ।

**O(n²): কোয়াড্রাটিক**
```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        cout << i << j;     // n * n বার চলে
```

**O(2ⁿ): এক্সপোনেনশিয়াল**
```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // প্রতিবার দুটি রিকার্সিভ কল
}
```
প্রতিটি কল থেকে আরও দুটি কল তৈরি হয়, ফলে n এক বাড়লে কলের সংখ্যা প্রায় দ্বিগুণ হয়।

## 7. লুপ বিশ্লেষণ

| কোডের ধরন | পুনরাবৃত্তি | কমপ্লেক্সিটি |
|---|---|---|
| `for (i = 0; i < n; i++)` | n | O(n) |
| `for (i = 0; i < n; i += 2)` | n/2 | O(n) |
| `for (i = 1; i < n; i *= 2)` | log₂ n | O(log n) |
| `for (i = n; i > 1; i /= 2)` | log₂ n | O(log n) |
| `for (i = 0; i * i < n; i++)` | √n | O(√n) |
| দুটি নেস্টেড লুপ, প্রতিটি n পর্যন্ত | n × n | O(n²) |
| বাইরের লুপ n পর্যন্ত, ভেতরে `j *= 2` | n × log n | O(n log n) |
| পরপর দুটি লুপ | n + n | O(n) |

### নির্ভরশীল নেস্টেড লুপ

```cpp
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= i; j++)
        count++;
```

ভেতরের লুপ চলে 1, 2, 3, ..., n বার। মোট:

```
1 + 2 + 3 + ... + n = n(n + 1) / 2 = (n² + n) / 2
```

ধ্রুবক ও নিম্নমানের পদ বাদ দিলে **O(n²)**।

### গুণিতক ভেতরের লুপসহ উদাহরণ

```cpp
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        count++;
```

বাইরের লুপ n বার, ভেতরের লুপ log n বার। মোট **O(n log n)**।

## 8. বেস্ট, ওয়ার্স্ট ও এভারেজ কেস

অনেক অ্যালগরিদমের চলার সময় শুধু ইনপুটের আকারের ওপর নয়, ইনপুটের **সজ্জার** ওপরও নির্ভর করে।

n এলিমেন্টের অ্যারেতে লিনিয়ার সার্চের উদাহরণ:

| কেস | পরিস্থিতি | তুলনার সংখ্যা | কমপ্লেক্সিটি |
|---|---|---|---|
| **বেস্ট কেস** | কী প্রথম এলিমেন্টেই আছে | 1 | O(1) |
| **ওয়ার্স্ট কেস** | কী সবশেষে আছে বা নেই | n | O(n) |
| **এভারেজ কেস** | কী যেকোনো স্থানে থাকার সম্ভাবনা সমান | প্রায় n/2 | O(n) |

- **ওয়ার্স্ট কেস** একটি নিশ্চয়তা দেয়: অ্যালগরিদম এর চেয়ে ধীর হবে না। এটিই সবচেয়ে বেশি ব্যবহৃত হয়।
- **বেস্ট কেস** খুব আশাবাদী, তাই কম কাজে লাগে।
- **এভারেজ কেস** কাজের, কিন্তু ইনপুটের বণ্টন সম্পর্কে অনুমান প্রয়োজন।

**গুরুত্বপূর্ণ:** বেস্ট, ওয়ার্স্ট, এভারেজ হলো ইনপুটের *কেস*। বিগ-ও, ওমেগা, থেটা হলো সীমার *নোটেশন*। এ দুটি আলাদা ধারণা। যেমন বলা যায়, "লিনিয়ার সার্চের ওয়ার্স্ট কেস Θ(n)।"

**উদাহরণ: কুইক সর্ট।** এভারেজ কেস O(n log n), ওয়ার্স্ট কেস O(n²) (যখন পিভট সবসময় সবচেয়ে ছোট বা সবচেয়ে বড় এলিমেন্ট হয়)।

## 9. স্পেস কমপ্লেক্সিটি

**স্পেস কমপ্লেক্সিটি** হলো n এর ফাংশন হিসেবে অ্যালগরিদমের প্রয়োজনীয় অতিরিক্ত মেমরি।

```
মোট স্পেস = ইনপুট স্পেস + অক্সিলিয়ারি স্পেস
```

- **ইনপুট স্পেস:** ইনপুট নিজে যে মেমরি নেয়।
- **অক্সিলিয়ারি স্পেস:** অ্যালগরিদম যে অতিরিক্ত মেমরি ব্যবহার করে (অস্থায়ী চলক, অতিরিক্ত অ্যারে, রিকার্সন স্ট্যাক)।

সাধারণত "স্পেস কমপ্লেক্সিটি" বলতে **অক্সিলিয়ারি স্পেস** বোঝানো হয়।

### উদাহরণ

**O(1) স্পেস:**
```cpp
int sum(int a[], int n) {
    int s = 0;                 // কয়েকটি চলক মাত্র, n এর ওপর নির্ভর করে না
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}
```

**O(n) স্পেস:**
```cpp
int* copyArray(int a[], int n) {
    int* b = new int[n];       // n আকারের অতিরিক্ত অ্যারে
    for (int i = 0; i < n; i++) b[i] = a[i];
    return b;
}
```

**O(n²) স্পেস:** n × n আকারের ম্যাট্রিক্স তৈরি করা।

### রিকার্সন ও স্পেস

প্রতিটি রিকার্সিভ কল **কল স্ট্যাকে** জমা থাকে। রিকার্সন n স্তর গভীর হলে কোনো অ্যারে না বানালেও O(n) স্পেস লাগে।

```cpp
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```
টাইম: O(n)। স্পেস: **O(n)**, কারণ সবচেয়ে গভীর অবস্থায় n টি কল স্ট্যাকে অপেক্ষা করে।

একই ফাংশনের ইটারেটিভ সংস্করণে স্পেস লাগে **O(1)**।

### প্রচলিত অ্যালগরিদমের স্পেস

| অ্যালগরিদম | অক্সিলিয়ারি স্পেস |
|---|---|
| বাবল, সিলেকশন, ইনসারশন সর্ট | O(1) |
| মার্জ সর্ট | O(n) |
| কুইক সর্ট (এভারেজ) | O(log n) স্ট্যাক |
| হিপ সর্ট | O(1) |
| বাইনারি সার্চ (ইটারেটিভ) | O(1) |
| বাইনারি সার্চ (রিকার্সিভ) | O(log n) |
| V টি ভার্টেক্সের গ্রাফে DFS / BFS | O(V) |

## 10. রিকার্সিভ অ্যালগরিদমের বিশ্লেষণ

রিকার্সিভ অ্যালগরিদমের জন্য আমরা একটি **রিকারেন্স রিলেশন** লিখি: এটি এমন একটি সমীকরণ, যা ছোট ইনপুটের সময়ের মাধ্যমে T(n) প্রকাশ করে।

### 10.1 রিকারেন্সের উদাহরণ

| অ্যালগরিদম | রিকারেন্স | সমাধান |
|---|---|---|
| ফ্যাক্টোরিয়াল | T(n) = T(n-1) + O(1) | O(n) |
| বাইনারি সার্চ | T(n) = T(n/2) + O(1) | O(log n) |
| মার্জ সর্ট | T(n) = 2T(n/2) + O(n) | O(n log n) |
| নাইভ ফিবোনাচ্চি | T(n) = T(n-1) + T(n-2) + O(1) | O(2ⁿ) |
| টাওয়ার অব হ্যানয় | T(n) = 2T(n-1) + O(1) | O(2ⁿ) |

### 10.2 পদ্ধতি ১: সাবস্টিটিউশন (আনরোলিং)

T(n) = T(n-1) + 1 সমাধান করি, যেখানে T(0) = 1।

```
T(n) = T(n-1) + 1
     = T(n-2) + 1 + 1
     = T(n-3) + 1 + 1 + 1
     ...
     = T(0) + n
     = n + 1          ->  O(n)
```

### 10.3 পদ্ধতি ২: রিকার্সন ট্রি (মার্জ সর্ট)

T(n) = 2T(n/2) + n

```
স্তর 0:   n                          -> মোট কাজ n
স্তর 1:   n/2   n/2                  -> মোট কাজ n
স্তর 2:   n/4 n/4 n/4 n/4            -> মোট কাজ n
...
স্তর k:   2^k টি নোড, প্রতিটি n/2^k  -> মোট কাজ n
```

ট্রিতে **log₂ n টি স্তর** আছে এবং প্রতি স্তরে **n** কাজ হয়। মোট = **O(n log n)**।

### 10.4 পদ্ধতি ৩: মাস্টার থিওরেম (সরলীকৃত)

নিচের আকারের রিকারেন্সের জন্য

```
T(n) = a * T(n / b) + O(n^d)       যেখানে a >= 1, b > 1, d >= 0
```

| শর্ত | ফলাফল |
|---|---|
| a < bᵈ | T(n) = O(nᵈ) |
| a = bᵈ | T(n) = O(nᵈ log n) |
| a > bᵈ | T(n) = O(n^(log_b a)) |

**উদাহরণ:**

- মার্জ সর্ট: a = 2, b = 2, d = 1। এখানে a = bᵈ (2 = 2), তাই T(n) = **O(n log n)**।
- বাইনারি সার্চ: a = 1, b = 2, d = 0। এখানে a = bᵈ (1 = 1), তাই T(n) = **O(log n)**।
- T(n) = 4T(n/2) + n: a = 4, b = 2, d = 1। এখানে a > bᵈ (4 > 2), তাই T(n) = O(n^(log₂ 4)) = **O(n²)**।
- T(n) = T(n/2) + n: a = 1, b = 2, d = 1। এখানে a < bᵈ (1 < 2), তাই T(n) = **O(n)**।

**মনে রাখুন:** T(n) = T(n-1) + T(n-2) এর মতো রিকারেন্সে মাস্টার থিওরেম প্রযোজ্য নয়। সেক্ষেত্রে রিকার্সন ট্রি বা আনরোলিং ব্যবহার করুন।

## 11. অ্যামরটাইজড অ্যানালাইসিস

কখনো কখনো একটি অপারেশন মাঝেমধ্যে ব্যয়বহুল হয়, কিন্তু বেশিরভাগ অপারেশন সস্তা। **অ্যামরটাইজড অ্যানালাইসিস** অপারেশনের একটি ধারার ওপর **প্রতি অপারেশনের গড় খরচ** দেয়, এতে কোনো সম্ভাবনা ব্যবহার করা হয় না।

### উদাহরণ: ডায়নামিক অ্যারে (C++ এর `vector`)

অ্যারে ভরে গেলে **দ্বিগুণ** আকারের নতুন অ্যারে তৈরি হয় এবং সব এলিমেন্ট কপি করা হয়।

- বেশিরভাগ `push_back` এর খরচ O(1)।
- মাঝেমধ্যে একটির খরচ O(n), কারণ কপি করতে হয়।

n টি ইনসারশনে কপি হয় আকার 1, 2, 4, 8, ..., n এ। মোট কপির কাজ:

```
1 + 2 + 4 + ... + n  <  2n
```

n টি ইনসারশনের মোট খরচ 3n এর কম, অতএব **প্রতি ইনসারশনের অ্যামরটাইজড খরচ O(1)**।

**এভারেজ কেস থেকে পার্থক্য:** অ্যামরটাইজড অ্যানালাইসিস হলো অপারেশনের ধারার ওপর ওয়ার্স্ট কেসের নিশ্চয়তা। এভারেজ কেস নির্ভর করে ইনপুট সম্পর্কে সম্ভাবনার অনুমানের ওপর।

## 12. টাইম-স্পেস ট্রেড-অফ

প্রায়ই বেশি মেমরি ব্যবহার করে অ্যালগরিদম দ্রুত করা যায়, অথবা ধীর গতি মেনে নিয়ে মেমরি বাঁচানো যায়।

**উদাহরণ: ফিবোনাচ্চি**

| পদ্ধতি | টাইম | স্পেস |
|---|---|---|
| নাইভ রিকার্সন | O(2ⁿ) | O(n) |
| মেমোইজেশন (হিসাব করা ফলাফল অ্যারেতে রাখা) | O(n) | O(n) |
| দুটি চলক দিয়ে ইটারেটিভ | O(n) | O(1) |

**উদাহরণ: অ্যারেতে ডুপ্লিকেট যাচাই**

| পদ্ধতি | টাইম | স্পেস |
|---|---|---|
| প্রতিটি জোড়া তুলনা | O(n²) | O(1) |
| আগে সর্ট, তারপর পাশাপাশি যাচাই | O(n log n) | O(1) বা O(n) |
| হ্যাশ সেট ব্যবহার | O(n) এভারেজ | O(n) |

সব ক্ষেত্রে সেরা কোনো একক পছন্দ নেই। সমস্যার কনস্ট্রেইন্টের ওপর সঠিক পছন্দ নির্ভর করে।

## 13. প্রচলিত ডেটা স্ট্রাকচার ও অ্যালগরিদমের কমপ্লেক্সিটি

### ডেটা স্ট্রাকচারের অপারেশন

| ডেটা স্ট্রাকচার | অ্যাক্সেস | সার্চ | ইনসার্ট | ডিলিট |
|---|---|---|---|---|
| অ্যারে | O(1) | O(n) | O(n) | O(n) |
| সিঙ্গলি লিংকড লিস্ট | O(n) | O(n) | হেডে O(1) | হেডে O(1) (নোড জানা থাকলে) |
| স্ট্যাক | O(n) | O(n) | O(1) | O(1) |
| কিউ | O(n) | O(n) | O(1) | O(1) |
| হ্যাশ টেবিল | প্রযোজ্য নয় | এভারেজ O(1), ওয়ার্স্ট O(n) | এভারেজ O(1), ওয়ার্স্ট O(n) | এভারেজ O(1), ওয়ার্স্ট O(n) |

### সার্চিং ও সর্টিং অ্যালগরিদম

| অ্যালগরিদম | বেস্ট | এভারেজ | ওয়ার্স্ট | স্পেস | স্টেবল |
|---|---|---|---|---|---|
| লিনিয়ার সার্চ | O(1) | O(n) | O(n) | O(1) | প্রযোজ্য নয় |
| বাইনারি সার্চ | O(1) | O(log n) | O(log n) | O(1) | প্রযোজ্য নয় |
| বাবল সর্ট | O(n) | O(n²) | O(n²) | O(1) | হ্যাঁ |
| সিলেকশন সর্ট | O(n²) | O(n²) | O(n²) | O(1) | না |
| ইনসারশন সর্ট | O(n) | O(n²) | O(n²) | O(1) | হ্যাঁ |
| মার্জ সর্ট | O(n log n) | O(n log n) | O(n log n) | O(n) | হ্যাঁ |
| কুইক সর্ট | O(n log n) | O(n log n) | O(n²) | O(log n) | না |

**তথ্য:** তুলনাভিত্তিক যেকোনো সর্টিং অ্যালগরিদমের ওয়ার্স্ট কেসে কমপক্ষে Ω(n log n) তুলনা লাগে। তাই মার্জ সর্ট ও হিপ সর্ট তুলনাভিত্তিক সর্টের মধ্যে অপ্টিমাল।

## 14. কনস্ট্রেইন্ট দেখে অ্যালগরিদম নির্বাচন

একটি সাধারণ কম্পিউটার প্রতি সেকেন্ডে প্রায় **10⁸ টি সরল অপারেশন** করতে পারে। সময়সীমা ১ সেকেন্ড হলে ইনপুট সাইজ n দেখে বুঝে নিন কোন কমপ্লেক্সিটি গ্রহণযোগ্য:

| ইনপুট সাইজ n | গ্রহণযোগ্য কমপ্লেক্সিটি |
|---|---|
| n <= 10 | O(n!) |
| n <= 20 | O(2ⁿ) |
| n <= 500 | O(n³) |
| n <= 5,000 | O(n²) |
| n <= 10⁶ | O(n log n) |
| n <= 10⁸ | O(n) |
| n > 10⁸ | O(log n) বা O(1) |

n = 1,00,000 হলে O(n²) সমাধানে 10¹⁰ অপারেশন লাগে, যা অনেক ধীর। O(n log n) সমাধানে লাগে প্রায় ১৭ লাখ অপারেশন, যা মুহূর্তেই শেষ হয়।

## 15. সাধারণ ভুলসমূহ

1. **কেস ও নোটেশন গুলিয়ে ফেলা।** ওয়ার্স্ট কেস আর বিগ-ও এক জিনিস নয় (অধ্যায় ৮ দেখুন)।
2. **লুকানো খরচ উপেক্ষা করা।** স্ট্রিংয়ে `s = s + str` এর মতো একটি লাইনেও কপি করার কারণে O(n) খরচ হতে পারে।
3. **একটি লুপ মানেই O(n) ধরে নেওয়া।** লুপ চলকটি কীভাবে বদলায় তা দেখুন। `i *= 2` হলে O(log n)।
4. **রিকার্সন স্ট্যাকের স্পেস ভুলে যাওয়া।** n গভীরতার রিকার্সিভ ফাংশন O(n) মেমরি নেয়।
5. **শুধু একটি ইনপুট সাইজ ধরা।** দুটি ইনপুট থাকলে (যেমন a ও b আকারের দুটি অ্যারে) দুটি চলকই ব্যবহার করুন।
6. **বিগ-ও কে সঠিক সময় ভাবা।** বিগ-ও বৃদ্ধির হার বোঝায়, সেকেন্ড নয়। বিশাল ধ্রুবকসহ O(n) অ্যালগরিদম বাস্তবে ছোট ইনপুটে O(n log n) অ্যালগরিদমের চেয়ে ধীর হতে পারে।

## 16. P ও NP পরিচিতি

এটি একটি উচ্চতর বিষয়, সচেতনতার জন্য রাখা হয়েছে।

- **ক্লাস P:** যেসব সমস্যা পলিনোমিয়াল সময়ে (O(n), O(n²), O(n³) ইত্যাদি) **সমাধান** করা যায়। উদাহরণ: সর্টিং, সার্চিং, শর্টেস্ট পাথ।
- **ক্লাস NP:** যেসব সমস্যার সমাধান পলিনোমিয়াল সময়ে **যাচাই** করা যায়। P এর প্রতিটি সমস্যাই NP এর অন্তর্গত।
- **NP-complete:** NP এর সবচেয়ে কঠিন সমস্যাগুলো। এদের যেকোনো একটি পলিনোমিয়াল সময়ে সমাধান করা গেলে সবগুলোই করা যাবে। উদাহরণ: ট্রাভেলিং সেলসম্যান (ডিসিশন সংস্করণ), সাবসেট সাম, বুলিয়ান স্যাটিসফায়াবিলিটি (SAT)।

**P = NP কি না** তা কম্পিউটার সায়েন্সের সবচেয়ে বড় অমীমাংসিত সমস্যাগুলোর একটি। NP-complete সমস্যার জন্য বর্তমানে কোনো পলিনোমিয়াল সময়ের অ্যালগরিদম জানা নেই, তাই বাস্তবে আমরা আনুমানিক (approximation) বা হিউরিস্টিক পদ্ধতি ব্যবহার করি।

## 17. অনুশীলনী

নিচের প্রতিটি কোডের টাইম কমপ্লেক্সিটি নির্ণয় করুন।

**সমস্যা ১**
```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < 100; j++)
        x++;
```

**সমস্যা ২**
```cpp
for (int i = n; i >= 1; i /= 2)
    x++;
```

**সমস্যা ৩**
```cpp
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        x++;
```

**সমস্যা ৪**
```cpp
for (int i = 0; i < n; i++)
    x++;
for (int j = 0; j < m; j++)
    y++;
```

**সমস্যা ৫**
```cpp
void f(int n) {
    if (n <= 1) return;
    f(n / 2);
    f(n / 2);
    for (int i = 0; i < n; i++) x++;
}
```

**সমস্যা ৬**
n এলিমেন্টের অ্যারেতে রিকার্সিভ বাইনারি সার্চের স্পেস কমপ্লেক্সিটি কত?

### উত্তর

1. **O(n)।** ভেতরের লুপ ধ্রুবক ১০০ বার চলে। মোট 100n, অতএব O(n)।
2. **O(log n)।** প্রতিবার i এর মান অর্ধেক হয়।
3. **O(n²)।** ভেতরের লুপ চলে n, n-1, ..., 1 বার। মোট n(n+1)/2।
4. **O(n + m)।** লুপ দুটি পরপর এবং ভিন্ন চলক ব্যবহার করে।
5. **O(n log n)।** রিকারেন্স T(n) = 2T(n/2) + n, মার্জ সর্টের মতোই।
6. **O(log n)।** রিকার্সনের গভীরতা log₂ n এবং প্রতি স্তরে ধ্রুবক স্পেস লাগে।

## 18. সারসংক্ষেপ

- কমপ্লেক্সিটি মাপে ইনপুট সাইজ n এর সাথে সময় ও মেমরি কীভাবে **বাড়ে**, সঠিক সেকেন্ড নয়।
- **বিগ-ও** ঊর্ধ্বসীমা, **ওমেগা** নিম্নসীমা এবং **থেটা** সুনির্দিষ্ট সীমা বোঝায়।
- ধ্রুবক ও নিম্নমানের পদ বাদ দিন। পরপর থাকা অংশ যোগ করুন। নেস্টেড অংশ গুণ করুন।
- বৃদ্ধির ক্রম: `1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!`
- লুপে অর্ধেক বা দ্বিগুণ করলে **log n** হয়।
- রিকার্সনে **স্ট্যাক স্পেস** লাগে। রিকারেন্স, রিকার্সন ট্রি বা মাস্টার থিওরেম দিয়ে রিকার্সন বিশ্লেষণ করুন।
- **অ্যামরটাইজড** অ্যানালাইসিস অপারেশনের ধারার প্রকৃত গড় খরচ দেয়।
- দ্রুত অ্যালগরিদমে প্রায়ই বেশি মেমরি লাগে (**টাইম-স্পেস ট্রেড-অফ**)।
- ইনপুটের কনস্ট্রেইন্ট দেখে গ্রহণযোগ্য কমপ্লেক্সিটি ঠিক করুন।
